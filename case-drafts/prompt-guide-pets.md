> Это бриф для генерации **текста** и **картинок** двух кейсов в портфолио Егора Шугаева.
> Схема та же, что отработала на менторском кейсе: GPT даёт текст по полям + арт, потом Егор передаёт результат на вёрстку.
>
> **Как пользоваться:** скопируй этот файл целиком в GPT. Сначала попроси текст (Часть 2 и 3), потом картинки (Часть 4). Верни всё Егору — он соберёт в `projects.ts`.

## ЧАСТЬ 1. Общий контекст (читать обязательно, применяется к обоим кейсам)

**Где это живёт.** Портфолио дизайн-директора. Раздел «Эксперименты» (`/experiments`) — пет-проекты на стыке дизайна, кода и AI. Эти два кейса — туда. Каждый открывается на отдельной странице кейса (`/cases/<slug>`) с обложкой, секциями, цифрами, ссылками.

**Кто автор и тон.** Егор — дизайн-директор, 7 лет управления (МТС, Ozon, Газпром Нефть), сейчас в поиске. Пишет от первого лица, по-русски, на «ты» к читателю не обращается — это рассказ о себе.

**Голос — критично, GPT по дефолту пишет не так:**
- Сухо, по-человечески, без пафоса. Как будто рассказываешь коллеге, а не продаёшь.
- **Запрещено:** эм-дэши как связки («— это —»); конструкция «не просто X, а Y»; «правило трёх» (перечисления из трёх ради ритма); раздутые выводы в конце абзаца; слова «инновационный», «уникальный», «прорывной», «бесшовный» (кроме конкретного UX-смысла).
- Это пет-проекты. Не надо делать вид, что это продукт на миллион. Честно: «вожусь», «пробую», «где-то получилось, где-то бросил». Лёгкая самоирония уместна.
- Цифры — только реальные. Если цифры нет — не выдумывай, лучше качественная формулировка.

**Визуальный стиль сайта (для понимания контекста, влияет на картинки):**
- Фон чёрный (`#0a0a0a` / `#0E0E0E`). Тёмная брутальная техно-эстетика.
- Акцент — кислотно-лаймовый `#A6FF00` (вторичный `#B8FF33`). Используется точечно: цифры, точки, hover.
- Шрифт заголовков — гротеск P95, всё капсом. Подписи — моноширинный.
- Сетка карточек скруглённая (rounded-2xl), тонкие белые рамки `rgba(255,255,255,0.06)`.

**Структура текста кейса (поля, которые нужно заполнить).** Формат как у «рабочих» кейсов портфолио:

| Поле | Что это | Лимит |
|---|---|---|
| `title` | Заголовок кейса, капсом на сайте | 3–6 слов, глагол приветствуется |
| `description` | Текст на карточке в сетке | 2–3 предложения, 220–320 знаков |
| `longDescription` | Вводный абзац на странице кейса | 1 абзац, 400–700 знаков |
| `tags` | Теги-чипы | 3–5 шт, по 1–2 слова (англ. термины ок: Three.js, GLSL) |
| `metric` + `metricLabel` | Крупная цифра на карточке (опц.) | value короткий («30с»), label 2–4 слова |
| `results` | Блок итоговых цифр | 2–4 шт: value + label |
| `sections[]` | Смысловые блоки | см. ниже |

Каждая секция — это либо `{title, content}` (простой абзац), либо богатый формат:
- `context` — что было / в чём суть (1–3 предложения)
- `approach` — что я делал / как устроено (1–4 предложения, можно с `**жирными**` подзаголовками внутри)
- `result` — что вышло (1–3 предложения)
- `callouts[]` — мини-цифры внутри секции: value + label (2–4 шт)
- `links[]` — ссылки-пруфы рядом с текстом: label + url + kind (`site`/`github`/`video`/`article`)

Просьба к GPT: верни текст **по этим полям, размеченный**, чтобы Егор просто вставил значения. Не выдумывай TypeScript — отдай как структуру «поле: значение».

## ЧАСТЬ 2. Кейс «Гиперкуб» (slug: `webgl-experiments`)

**О чём проект — фактура (опирайся на это, не выдумывай новое):**
Пет-проект на стыке дизайна и creative coding. Анимированные стеклянные 3D-фигуры (куб, октаэдр, икосаэдр, в планах додекаэдр) с внутренней светящейся геометрической сеткой. Эффекты: преломление, fresnel, bloom, морфинг между формами, post-processing (chromatic aberration). Стек: **Three.js + кастомные GLSL-шейдеры, SDF (signed distance functions)**. Алгоритмы: lattice points для внутренней сетки, fresnel для стекла, морфинг через интерполяцию геометрий.

**Зачем Егор это делает (мотив, важен для голоса):** руками щупает современные инструменты на production-уровне, а не «по туториалу». Хочет нащупать, где заканчивается дизайн и начинается creative coding. Честно: что-то выходит с первого раза, что-то перепробовал десяток подходов и бросил. Куб с сеткой работает; обобщение алгоритма на произвольные формы — в процессе; с додекаэдром рендер сетки пока сломан.

**Что нужно от GPT по тексту:**
- Улучшить и дописать `description`, `longDescription`, секции. Сохранить честный пет-тон, без раздувания.
- Секции (предложение, можно корректировать): **Идея** → **Как устроено / технологии** → **Что работает, что нет (статус)**. Можно добавить секцию **Зачем мне это** (мотив, рост навыка) — это сильная часть для дизайн-директора, который сам кодит.
- `results` / `callouts`: только реальное. Возможные честные метрики: число форм, стек («Three.js + GLSL»), статус («куб готов, додекаэдр в работе»). **Не выдумывать просмотры/звёзды/пользователей** — это пет-проект, не продукт.
- `tags`: Three.js, GLSL, WebGL, Creative Coding, Shaders (выбрать 3–5).

**Ссылки — ВСТАВИТ ЕГОР (отметить плейсхолдерами, GPT не выдумывает URL):**
- [ ] Живое демо (если задеплоено) — `kind: "site"`
- [ ] GitHub-репозиторий — `kind: "github"`
- [ ] Видео-разбор / запись экрана, если выложено — `kind: "video"`

> Егор: проверь, есть ли репо/демо под это. Если нет — секцию ссылок оставляем пустой, не выдумываем.

## ЧАСТЬ 3. Кейс «Telegram dashboard» (slug: `telegram-dashboard`)

**О чём проект — фактура:**
Автоматизация контента для авторского Telegram-канала Егора про AI — **«Снятся ли Егору нейросети»**. Telegram-бот принимает материалы (ссылки, голосовые, скриншоты), транскрибирует через **Whisper API**, парсит статьи через **trafilatura**, генерирует черновик поста через **Claude API**. Стек: **Python, aiogram 3, FastAPI, SQLite + SQLAlchemy** (хранение сессий). Поток: «от ссылки до готового черновика за ~30 секунд».

**Зачем (мотив):** ведение канала съедало 2–3 часа в день (сбор материалов, транскрипция мыслей, сборка поста). Цель — снять рутину сборки, **не потеряв авторский голос**. Складывать заметки в Notion и раз в неделю превращать в посты — пробовал, не пошло, те же часы. Полностью убирать себя из цикла не пытается: голос пока умеет придумать только живой человек.

**Статус (честно):** этап 1 (скелет) в разработке. Базовый цикл работает: кидаешь ссылку/голосовое → `/go` → получаешь черновик. Авторский голос ловится не идеально, часть промптов переписывается каждую неделю.

**Что нужно от GPT по тексту:**
- Улучшить `description`, `longDescription`, секции. Тон — практик-разработчик, честно про «ещё сырое».
- Секции (предложение): **Проблема** (рутина канала) → **Решение / пайплайн** (как устроен бот) → **Статус** (что работает, что переписываю). Можно добавить **Дальше** (куда хочу довести).
- `metric`/`metricLabel`: «30с» / «от ссылки до черновика» (уже есть, можно оставить).
- `results` / `callouts`: реальные технические факты — стек, шаги пайплайна, время. Без выдуманных метрик аудитории, если Егор их не дал.
- `tags`: Python, Claude API, Telegram Bot, AI Automation, aiogram (выбрать 3–5).

**Ссылки — ВСТАВИТ ЕГОР:**
- [ ] Канал в Telegram «Снятся ли Егору нейросети» — `kind: "site"`
- [ ] GitHub-репозиторий бота (если публичный) — `kind: "github"`

## ЧАСТЬ 4. Картинки и видео

> **Главный принцип (честно):** для обоих кейсов лучшие ассеты — **реальные**, их GPT не сделает.
> - Гиперкуб: GPT не отрендерит твой конкретный шейдер. Реальный скринкаст демки → обложка-видео. У тебя уже есть `public/videos/web gl.MP4` — из него режется cover.
> - Telegram: мокап чата от GPT выйдет с кривым UI (не те иконки, шрифт, раскладка пузырей) — спалится перед теми, кто знает Telegram. Реальные скрины бота сильнее.
>
> Поэтому ниже разделено: **«реальное — снимаешь сам»** и **«что реально отдать GPT»** (абстрактный арт, обложки, постеры, фоны — там, где фотореализм UI не нужен).
>
> **Где GPT реально силён (и что зашло на менторском кейсе):** объясняющая концепт-картинка в стилистике сайта — схема пайплайна / идеи, которая заменяет стену текста. Эталон — `audio-to-session.png` из менторского кейса (диаграмма «аудио → структурированная сессия», hero секции). Цельтесь именно в такой формат: чёрный фон, лаймовый акцент, моно-подписи, поток слева направо. Это приоритетный тип ассета от GPT для обоих кейсов.

### Технические требования к ассетам (для всех картинок)
- **Обложка кейса (cover):** видео `.mp4` + постер `.png/.jpg`. Соотношение ~**16:9**, но карточка кропает по высоте — держи композицию по центру. Видео короткое (3–6 сек), без звука, зацикленное. Поведение: на карточке играет на hover, замирает на ~2.86 сек.
- **Hero-плакаты внутри секции (`heroes`):** **16:9**, full-width или сеткой. Это «постеры» секций без рамки телефона.
- **Скриншоты (`screenshots`):** для веб-проектов — **16:9**, 2 колонки. Для мобильных/телеграм — портрет (iPhone-пропорции), до 5 в ряд.
- **Палитра:** фон чёрный `#0a0a0a`/`#0E0E0E`, акцент лайм `#A6FF00`. Картинки должны жить на чёрном фоне, не белые.
- **Без текста на картинках** (или минимум) — подписи кладёт сайт. Если текст нужен — латиница/моно, капсом.
- **Разрешение:** обложки/hero — минимум 1920×1080. Скрины — по нативу.

### Блок Б — Telegram dashboard

**Реальное (снимаешь сам — приоритет):**
1. **Скрины реального бота в Telegram:** (а) кидаешь ссылку, (б) `/go`, (в) бот вернул черновик. 3–4 портретных скрина прямо из приложения. Замазать личное, если есть.
2. **Скринкаст потока** (опц.): 5–10 сек экранки «ссылка → /go → черновик» → cover-видео. Сильнее статики, потому что весь смысл проекта — скорость.
3. **Диаграмма пайплайна** (можно собрать самому или отдать GPT, см. ниже): материалы → Whisper/trafilatura → Claude → черновик.

**Что реально отдать GPT:**

A) **Диаграмма пайплайна** (GPT тут уместен — это схема, не фейк-UI). Prompt:
```
Clean technical pipeline diagram on black background (#0a0a0a). Left to right flow: "INPUT (link / voice / screenshot)" → "TRANSCRIBE (Whisper) + PARSE (trafilatura)" → "GENERATE (Claude API)" → "DRAFT POST". Nodes as thin-bordered rounded rectangles, white text, connectors and active accents in acid-lime green (#A6FF00). Monospace labels, uppercase. Minimal, brutalist, no decoration, 16:9.
```

B) **Cover-арт** (абстрактный, если скринкаста нет). Prompt:
```
Abstract dark composition representing an AI content automation bot: a stream of message bubbles and a paper-plane motif dissolving into structured text blocks, on pure black (#0a0a0a). Acid-lime green accents (#A6FF00), thin lines, monospace fragments, subtle glow. Techno-brutalist, minimal, no realistic UI, no real Telegram interface, no text paragraphs, 16:9, centered.
```
> Важно для GPT: **не рисовать реалистичный интерфейс Telegram** — выйдет фейково. Только абстракция/схема. Реальный UI — это твои скрины.
